# 🔥 Calories Tracker

Персональний трекер калорій (урізаний аналог Yazio) для одного користувача. PWA, розрахована на телефон; нова версія застосунку встановлюється, коли його згорнули, а не посеред введення.

Застосунок складається зі статичного фронтенду та Vercel Functions. Усі дані — записи щоденника, цілі, заміри, гра — зберігаються в Upstash Redis. У браузері лише знімок для миттєвого старту й черга змін, зроблених без мережі (див. «Офлайн»).

## Увага: сайт відкритий для всіх

Як і в recipe-book, автентифікації немає. Будь-хто, хто знає адресу, бачить і змінює дані.

## Розгортання на Vercel

1. Імпортуйте репозиторій у Vercel (Add New → Project; фреймворк і команди беруться з `vercel.json`).
2. **Storage → Upstash for Redis** (план Free) → підключіть до проєкту. Vercel сам додасть `KV_REST_API_URL` і `KV_REST_API_TOKEN`. База створюється порожньою — мокові дані є лише в локальній розробці (`.data/`, не комітиться).
3. **Settings → Environment Variables**: `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` (`npx web-push generate-vapid-keys`), `VAPID_SUBJECT` (`mailto:…`), `CRON_SECRET` (довгий випадковий рядок), `DISABLE_DEV_TOOLS=1` — див. `.env.example`.
4. Redeploy, щоб змінні підхопились. Крон `/api/cron` з’явиться у вкладці Cron Jobs сам (з `vercel.json`).
5. Не запускайте `npm run seed` проти продакшну (скрипт і так вимагає `--force` для нелокальної адреси).

## Локальна розробка

Потрібен Node.js 22+.

```bash
npm install
npm run dev         # http://127.0.0.1:5173 — Vite + локальний API (порт 5174) з Redis у пам’яті
npm run dev:vercel  # vercel dev зі справжнім Redis (потрібен vercel link і змінні середовища)
npm run preview     # продакшн-збірка + локальний API
npm run build       # перевірка типів + збірка в dist/
npm test            # тести валідації та API
npm run lint
```

Локальні секрети (напр. `GEMINI_API_KEY` для фото етикетки) — у файлі `.env.local` або `.env` у корені: локальний API читає їх сам (обидва в `.gitignore`).

Локальні дані зберігаються у `.data/dev-redis.json` і переживають перезапуск. Якщо база порожня, локальний сервер сам додає мокові дані: 15 страв у «Мої страви» і записи на сьогодні (вимкнути: `NO_SEED=1`). Щоб почати з нуля, видаліть цей файл.

`npm run seed -- https://<app>.vercel.app` заливає ті самі мокові дані на задеплоєну версію (повторний запуск нічого не дублює).

**Dev-панель** (кнопка DEV ліворуч унизу): тестування гейміфікації — додати калокоїни/щити, задати стрік, зсунути останню активність (перевірка порятунку й скидання серії), скинути денні нагороди, видати будь-яку ачівку, показати справжні іконки замість замочків, скинути гру. Серверні dev-дії вимикаються змінною `DISABLE_DEV_TOOLS=1`. У `npm run dev` вона видна завжди, а на Vercel — після відкриття `/?dev` (`/?dev=0` вимикає).

## Структура

```
api/        Vercel Functions: day, entries, profile, body, foods, game, search, stats, push, cron, ai
server/     HTTP-помічники та доступ до Redis (поза api/, щоб не стали функціями)
shared/     модель, валідація, розрахунок БЖВ — спільне для сервера й клієнта (JS + JSDoc)
src/        React-клієнт
  data/       API-клієнт і Zustand-стор з оптимістичними змінами
  features/   екрани та модалки
  components/ UI-примітиви
scripts/    локальний API-сервер, Redis у пам’яті
tests/      node --test
```

Серверний код написаний на JS з JSDoc, а не на TS: Vercel запускає його без компіляції, а TypeScript 7 не має JS API, через який Vercel компілює `api/*.ts`. Типи все одно перевіряються в strict-режимі (`tsconfig.api.json`, `checkJs`).

## Redis

| Ключ | Тип | Вміст |
|---|---|---|
| `ct:day:<YYYY-MM-DD>` | hash | id запису → Entry |
| `ct:profile` | string | `{ goals, targetWeight, updatedAt }` |
| `ct:foods` | hash | id → Food («Мої страви») |
| `ct:body` | hash | дата → вага й об’єми (груди, талія, стегна) |
| `ct:game` | string | гейміфікація: калокоїни (`coins`), стрік, щити, видані нагороди, ачівки |
| `ct:ean:<штрихкод>` | string | результат пошуку за штрихкодом: знайдене — 30 діб, «немає» — доба, неповна відповідь — 10 хв |
| `ct:search:<запит>` | string | кеш публічного пошуку (Сільпо, Zakaz.ua, Open Food Facts), TTL 1 доба; неповна відповідь — 10 хв |
| `ct:summary` | hash | дата → підсумок дня (ккал, БЖВ, к-сть записів, знімок норм) — для статистики; оновлюється при кожній зміні записів |
| `ct:usage` | hash | id страви → `{ n, last }` — «Нещодавні» й «Часті» в пошуку; оновлюється, коли запис додано зі страви (`PUT /api/entries?…&food=<id>`), а для старої історії будується один раз за назвами страв (`ct:usage:ready`) |
| `ct:summary:ready` | string | позначка, що підсумки вже побудовано з наявних днів (разова міграція при першому `GET /api/stats`) |

## API

| Метод і шлях | Що робить |
|---|---|
| `GET /api/day?date=…` | записи дня |
| `PUT /api/entries?id=…[&source=copy]` `{entry}` | створити або замінити запис (id генерує клієнт); `source=copy` — перший запис «Скопіювати з учора» |
| `DELETE /api/entries?id=…&date=…` | видалити запис |
| `GET` / `PUT /api/profile` `{profile}` | денні цілі й цільова вага |
| `GET /api/body`, `PUT` / `DELETE /api/body?date=…` | заміри тіла (історія для графіка ваги) |
| `GET /api/foods`, `PUT` / `DELETE /api/foods?id=…` | «Мої страви» |
| `GET /api/game`, `POST /api/game` `{action}` | стан гри; `claim` — забрати нагороду ачівки, `seen` — модалку ачівки показано, `buy` / `use` `{item}` — купити й використати товар магазину, `theme` `{theme}` — увімкнути куплену тему, `dismissNotice`, `dev` — тестові дії |
| `GET /api/search?q=…` | публічний пошук: Сільпо → Zakaz.ua → Open Food Facts; лише продукти з калоріями (див. «Публічний пошук») |
| `GET /api/search?ean=…` | продукт за штрихкодом (сканер): ті самі джерела, перший знайдений; кеш 30 діб |
| `GET` / `POST` / `DELETE /api/push` | ключ VAPID і підписка пристрою на сповіщення; `{action:'test'}` — тестове |
| `GET /api/cron` | вечірні сповіщення (Vercel Cron о 20:00 UTC) |
| `GET /api/stats` | підсумки всіх днів із записами — графіки й теплова карта (одна команда Redis на весь рік) |

Конфлікти між пристроями: перемагає версія з більшим `updatedAt` (мітки з майбутнього понад добу сервер відхиляє).

Клієнт (`src/data/store.ts`) показує зміни одразу й відкочує їх, якщо сервер відмовив. Усі запити на зміну йдуть по черзі (`serial`), а фонове оновлення (повернення у вкладку, мережа, північ) не накриває дані, якщо за час запиту щось змінилося (`guardedLoad`). Видалений запис можна повернути з тосту «Повернути». Для записів «за вагою» сервер сам перераховує калорії й БЖВ з `per100` і `grams`.

## Щоденник

Головна згори донизу: «Залишилось» (підсумок дня), прийоми їжі, «Мої страви», «Мої параметри», «Як іде схуднення», «Статистика».

- **Додавання**: пошук з вкладками «Нещодавні / Часті / Усі» для «Моїх страв», «Скопіювати з учора», «Ввести вручну». Вага порції — з кнопками −10 / +10 г.
- **Порції** (як у Yazio): у страви з «Моїх страв» можна задати порції — штука, скибочка, шматок, порція, упаковка, склянка, ст. ложка, ч. ложка — і скільки грамів в одній. При додаванні обираєш порцію й кількість (крок ½: «2 штуки × 60 г = 120 г») замість того, щоб вводити грами. Задати порції — кнопкою «Додати порцію» / «Порції» на кроці ваги або при ручному введенні; у страви зі збережених вони зберігаються одразу, у страви з пошуку — разом із «Зберегти в мої страви» (перемикач вмикається сам). Поле `portions` у `Food` (`shared/model.js`, валідація — `sanitizePortions`). Запис, доданий порцією, пам'ятає її (`Entry.portion` = одиниця й кількість): у щоденнику — «2 штуки · 120 г», у редагуванні запису — лічильник порцій; ручна зміна грамів порцію знімає.
- **Мої страви** — плашка на головній (одразу під прийомами їжі) або «Керувати» біля «Мої страви» в пошуку; на кроці ваги збереженої страви — олівець. Список із пошуком, редагування назви, бренду, КБЖВ на 100 г, звичної ваги й порцій, нова страва, видалення з тостом «Повернути» (`src/features/foods/`). Записи щоденника мають власну копію цінності, тож зміни страви їх не торкаються. Видалення без мережі йде в чергу (`deleteFood` у `shared/outbox.js`); «Повернути» відновлює страву з тим самим id і датою створення.
- **Повтор**: порожній прийом їжі сьогодні, а вчора в ньому щось було, — кнопка «Як учора» (лише для сьогодні: при гортанні днів попередній день не підтягується) (копіює вчорашні страви цього прийому); у редагуванні запису — «Ще раз» (та сама страва ще одним записом).
- **Сканер штрихкоду** — кнопка в полі пошуку (`src/features/add/ScanStep.tsx`). Камера → код EAN-13, EAN-8 чи UPC-A (контрольна цифра перевіряється, той самий код двічі поспіль; UPC-E не підтримується). Штрихкоди зводяться до однієї форми (`canonicalEan`: GTIN-14 Zakaz.ua «04820…» → «4820…», EAN-8 з нулями → 8 цифр) → спершу «Мої страви» (миттєво й офлайн, за `Food.barcode`), потім `GET /api/search?ean=…`: Сільпо → Zakaz.ua → Open Food Facts. Знайшли — крок ваги; якщо в назві є вага («…840г», «0,9 л») — одразу порція «упаковка». Ніде немає — ручне введення, штрихкод збережеться зі стравою. Є поле «Або введіть код» (камера недоступна) і ліхтарик (Android). Пошук за кодом іде один раз (з камери чи з поля), камера вимикається одразу після коду, а відповідь, що прийшла після виходу з кроку, ігнорується. Розпізнавання (`src/lib/scanner.ts`): вбудований `BarcodeDetector` (Android Chrome), інакше `barcode-detector` на zxing-wasm (iPhone — у Safari вбудованого немає); WASM ~1 МБ вантажиться лише при першому відкритті сканера, з нашого сайту (не з CDN) і кешується сервіс-воркером.
- **Звідки цифри**: у публічному пошуку біля бренду — маленька іконка Сільпо, Auchan (Zakaz.ua) чи Open Food Facts (`public/sources/`). Шторка додавання не відкриває клавіатуру сама — спершу видно «Мої страви».
- **Видалення запису** — свайпом рядка вліво (або з форми редагування); тост «Повернути» скасовує.
- **Звуки** (`src/lib/sound.ts`): дзвін монети, закрита норма, серія, покупка, фанфара тижня серії й нова ачівка — синтезовані Web Audio, без бібліотек і файлів. Одна дія — один звук (найважливіший). На iPhone «фонова» аудіосесія: звуки змішуються з музикою й мовчать у беззвучному режимі. Звуки завжди увімкнені (глушить їх лише беззвучний режим телефона), послухати всі — у DEV-панелі.
- **Екран не гасне**, поки відкрита шторка додавання чи редагування їжі або калькулятор — зручно з кухонною вагою (Screen Wake Lock, `src/lib/wakeLock.ts`; без підтримки в браузері просто нічого не відбувається).
- **Календар** — тап по даті в шапці: місяць, розфарбований тепловою картою; тап по дню — перехід.
- **Досягнення**: у вітрині лише ще не отримані; отримані — списком за тапом на плашку «Отримано». Модалка нової ачівки чекає, поки закриють шторку (не перериває додавання їжі).

## Публічний пошук

Під «Моїми стравами» в пошуку — продукти з публічних каталогів (`api/search.js`). Джерела опитуються по черзі: наступне — лише коли попередні разом знайшли менше 5 продуктів або впали. Дублікати між джерелами (та сама назва) прибираються, перше джерело важливіше.

1. **Сільпо** (`server/silpo.js`) — основне джерело: українські назви, товари з полиць, харчова цінність на 100 г. Пошук Сільпо неточний, тож видачу (40 товарів) пересортовуємо самі (`server/catalog.js`): вище ті, де більше слів запиту («курячі яйця» → спершу яйця, потім філе), товари без жодного слова відкидаємо. Калорії є лише в картці товару, тому для 20 найкращих картки тягнемо паралельно (~150 мс). Товари без калорій у видачу не потрапляють.
2. **Zakaz.ua** (`server/zakaz.js`) — каталог Auchan (Київ): ті самі українські бренди й те, чого немає в Сільпо; і головний запас, якщо Сільпо закриє доступ. Калорії й БЖВ — прямо в результатах пошуку, тож це один запит. Видача пересортовується так само. Назви українською лише із заголовком `Accept-Language: uk`.
3. **Open Food Facts** (`server/off.js`) — останнє: бренди з інших країн, запити російською. Українських продуктів там мало.

Повна відповідь кешується на CDN і в Redis на добу, неповна (джерело впало, порожньо) — лише в Redis на 10 хвилин. Уся функція вкладається в 8,5 с (ліміт — 10 с): Сільпо й Zakaz.ua чекаємо не довше 3,5 с кожен, OFF — скільки лишилось.

**Увага:** API Сільпо й Zakaz.ua не публічні й не документовані — це ті, з якими працюють сайти silpo.ua і zakaz.ua. Формат можуть змінити або закрити доступ; тоді пошук сам перейде на наступне джерело, а відповідний файл у `server/` доведеться підправити. АТБ і Велмарт не підключені: у Велмарта немає онлайн-каталогу, а в АТБ харчова цінність на сайті бита (однакові цифри в різних товарів).

Страви з пошуку зберігаються в «Мої страви» з `source` = `silpo`, `zakaz` або `off`; `offCode` — номер товару в Сільпо або штрихкод (Zakaz.ua, OFF); назва поля історична.

## Норма на вихідних

У суботу й неділю норма калорій більша на `weekendBoost` % (за замовчуванням 15%, налаштовується в «Налаштуваннях», 0 — вимкнено): 2 000 у будні → 2 300 на вихідних. БЖВ не змінюються. Норму на дату дає `goalsForDate` (`shared/goals.js`) — нею користуються головний екран (позначка «вихідний +15%»), калькулятор, нагорода за норму калорій на сервері, підсумки днів для статистики й теплової карти.

## Як іде схуднення

Плашка під «Моїми параметрами» і шторка з подробицями (`src/features/insights/`); розрахунки — `shared/insights.js` (ті самі на клієнті й на сервері), за останні 28 днів:

- **Тренд і прогноз ваги** — пряма через зважування (лінійна регресія; денні коливання води згладжуються), потрібно ≥ 3 зважування за ≥ 7 днів. Темп у кг/тиж і дата цілі («ціль ≈ березень») — і на плашці ваги.
- **Реальний розхід** — середнє з'їдене + калорії фактичної зміни ваги (7 700 ккал ≈ 1 кг), як в адаптивних калькуляторах: враховує і активність, і неточності записів. Потрібно ≥ 7 днів із записами. Поза 1 200–5 000 ккал не показується — замість цього перевірка «Вага й записи не сходяться». Підказка «скільки їсти» для −0,25 / −0,5 / −0,75 кг/тиж (темпи, де виходить < 1 200 ккал, не пропонуються).
- **Перевірки**: темп (0,5–1% ваги на тиждень — норма), білок (1,6–2,2 г/кг), жири (≥ 0,6 г/кг), норма калорій, вихідні проти буднів, частка днів без записів.
- **Що дає найбільше калорій** — `GET /api/stats?foods=<дата>`: записи за 28 днів, групування за назвою, частки прийомів їжі; кеш у Redis до кінця доби (`ct:foodmix:<дата>`).

## Фото етикетки (Gemini)

Кнопка 📷 поруч зі штрихкодом у полі пошуку (і «Заповнити з фото етикетки» в ручному введенні — туди веде сканер, коли штрихкод ніде не знайдено): фото таблиці «Харчова цінність» чи тексту на звороті → Gemini → ручне введення з уже заповненими назвою, КБЖВ на 100 г і порцією «упаковка» (маса нетто). Цифри лише заповнюють поля — їх видно й можна виправити до збереження; якщо модель не впевнена, з'являється попередження.

- **Фото** — системна камера (`<input type="file" capture>`: у PWA на iPhone надійніше за getUserMedia). На телефоні стискається до ~1 600 px JPEG з урахуванням орієнтації (`src/lib/labelPhoto.ts`) — кілька десятків–сотень КБ.
- **Сервер** — `POST /api/ai { action: 'label', image, mimeType }` (`api/ai.js` + `server/gemini.js`): Interactions API, відповідь строго за JSON-схемою, `store: false`. У підказці моделі: кДж → ккал, «на порцію» → на 100 г, будь-яка мова етикетки, не вигадувати (немає таблиці — `found: false`). Відповідь очищується (межі КБЖВ, вага упаковки).
- **Ліміт**: не більше `AI_DAILY_LIMIT` (за замовчуванням 20) викликів на добу за датою сервера (`ct:ai:count:<дата>`) — сайт відкритий, тож це захищає кредит в AI Studio. Фото — до 3 МБ.
- `GET /api/ai` → `{ configured, left }`: без ключа кнопка фото на місці, але підказує, як увімкнути.

**Налаштування** (Vercel → Settings → Environment Variables): `GEMINI_API_KEY` — ключ з Google AI Studio; необов'язково `GEMINI_MODEL` (за замовчуванням `gemini-3.8-flash`) і `AI_DAILY_LIMIT`. В AI Studio варто виставити бюджетний ліміт. Ліміт тривалості функцій — 30 с (`vercel.json`), бо модель читає фото кілька секунд.

## Статистика й калькулятор

- **Статистика** (остання плашка на головній, під «Як іде схуднення»): тиждень стовпчиками, середнє й дефіцит за 7 завершених днів. У шторці — період (тиждень / місяць / 3 міс / рік), графіки калорій із лінією норми й дефіциту по днях, підсумки (дні із записами, середнє, сумарний дефіцит ≈ кг, середня точність) і **теплова карта дисципліни** — місяць календарем або рік сіткою тижнів, як коміти на GitHub.
- **Точність дня** (`shared/stats.js`): 1 − зважене середнє відхилень від норм (калорії 40%, білки 25%, жири й вуглеводи по 17,5%). Рівні карти: ≥ 85% — «точний день», ≥ 75%, ≥ 60%, решта. Норми беруться зі знімка в підсумку дня, тож зміна цілей не переписує історію. Сьогодні в середнє й дефіцит не входить — день ще триває.
- **Калькулятор порцій** (кнопка ліворуч унизу): скільки калорій (за замовчуванням — залишок дня) і, за бажанням, БЖВ → скільки грамів кожної з вибраних «Моїх страв» узяти. `shared/portion.js`: невід'ємні найменші квадрати, калорії — майже жорстка умова, БЖВ розподіляють їх між стравами; порція страви не більша за 3 типові (300–1000 г), тож недосяжний макрос просто підсвічується бурштиновим.

## Гейміфікація

Нагороди нараховує сервер, коли зберігається запис їжі (`api/entries.js` → `shared/game.js`). Тому видалення й повторне додавання запису нічого не дає: за кожен день зберігаються позначки «вже нараховано».

Досвіду (XP) і рівнів немає — єдина валюта й міра прогресу — **калокоїни**.

| За що | Калокоїни |
|---|---|
| Перший запис у прийомі їжі (до 4 на день) | +5 |
| Білок у межах ±10% від цілі (раз на день) | +15 |
| Калорії в межах ±10% від цілі — денна ціль (раз на день) | +25 |
| Кожні 7 днів безперервної серії | +100 |
| Ачівка | за складністю: від 10 до 1 300 |

Економіка: максимум за день — 60 калокоїнів (4 × 5 + 15 + 25), з бонусом серії ≈ 520 на тиждень ідеальної гри. Нагорода ачівки = зусилля (скільки днів звичайного ведення щоденника потрібно) × вимогливість (1 — просто робити; до 2,5 — влучати в норму чи не пропускати днів) × 10 калокоїнів (`rewardFor` у `shared/achievements.js`). Наприклад, «На вогні I» (7 днів поспіль) — 90 калокоїнів, «На вогні III» (100 днів) — 1 300.

- Нагороди лише за записи на сьогодні або вчора за місцевим часом (`X-TZ-Offset`); добова стеля калорій для лічильників — max(2 × ціль, 5000).
- **Вогник у HUD** сірий, поки сьогодні нічого не зараховано, і спалахує з першим записом (як у Duolingo). Вогник розпалюється з серією: 1–6 днів жовтий, 7+ помаранчевий (колір теми), 30+ червоний зі світінням, 100+ розпечений — найщільніша заливка й сильніше світіння (`src/features/game/flameTier.ts`; світіння — box-shadow, не SVG-фільтр). Подивитися всі стани — DEV-панель → «Серія — перегляд» (підмінює стан лише локально). Тап — шторка «Серія» (`src/features/game/StreakSheet.tsx`): чи зараховано сьогодні (і що буде з пропусками: безкоштовний, скільки заморозок витратить, чи серію вже не врятувати), ланцюжок за 2 тижні (🔥 запис, 🎁 безкоштовний пропуск, ❄️ заморозка), прогрес до тижневого бонусу, рекорд і наступна ачівка за серію, заморозки, повернення обірваної серії «Супер вогником». Логіка — `shared/streak.js` (ті самі правила, що в `registerActivity`).
- Стрік: учора → +1. Перший пропущений день безкоштовний — серія триває, щити-заморозки не витрачаються. Кожен наступний пропущений день потребує 1 щит; якщо щитів не вистачає, серія починається з 1 (щити тоді не згорають), а обірвану серію ще можна повернути «Супер вогником». Коли серію врятовано, під HUD з'являється «Серію врятовано».
- Ачівки (`shared/achievements.js`): 39 штук у 5 категоріях — Щоденник, Серії, Харчування, Кухня, Калокоїни й інвентар; рівні бронза / срібло / золото / діамант. Лічильники для них рахує сервер разом із нагородами (`counters` у стані гри) з денними обмеженнями проти накрутки. «Ранній сніданок» і «нічний перекус» визначаються за місцевим часом: клієнт надсилає часовий пояс у заголовку `X-TZ-Offset`.
- Ачівка за складні рецепти вже є у вітрині, але почне рахуватися, коли з'явиться конструктор страв.

## Сповіщення

Пуш-сповіщення (Web Push) приходять щовечора близько 22:00 за Києвом: Vercel Cron викликає `/api/cron` о 20:00 UTC (на Hobby — у межах цієї години; улітку це 23:00 за Києвом). Що й коли — `shared/notify.js`; на день може прийти кілька, але кожне — лише з приводу:

| Сповіщення | Коли | Тексти |
|---|---|---|
| Порятунок серії | за день нічого не записано | випадковий із 4, не як минулого разу: «Твоя серія в 12 днів пише заповіт — Я так і знав.», «⚡ Терміново: 12-денна серія на межі зникнення — Записуй!», «Годі хавать і не записувать 🍔 — Я все бачу 👀», «Вогник на 12 днів просить дров 🪵 — Швидесенько!» |
| Заморозка | заморозку витратило | «Заморозку витратив ❄️ — Не звикай.» |
| Підсумок тижня | щонеділі (пн–нд) | менше 4 днів записано: «Записано 3 з 7 днів — А решта де?»; дефіцит: «Тиждень: −2 800 ккал — Молодець. Не розслабляйся.»; профіцит: «Тиждень: +2 100 ккал 🍰 — Ну ти дав.» |

На iPhone — лише в застосунку, доданому на головний екран (iOS 16.4+). Увімкнути, перевірити тестовим і вимкнути — у «Налаштуваннях». Підписки — `ct:push` у Redis (мертві прибираються самі), стан розсилки — `ct:push:state`.

| Змінна | Значення |
|---|---|
| `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` | пара ключів: `npx web-push generate-vapid-keys` (згенерувати один раз; приватний — нікому не показувати) |

## Офлайн

- **Записи без мережі не губляться.** Запис їжі, редагування, видалення, заміри, профіль і страви без інтернету не відкочуються, а лягають у чергу в localStorage (переживає закриття застосунку) і надсилаються по порядку, щойно з’явиться зв’язок — на старті, при поверненні в застосунок і за подією `online`. Скільки змін чекає — жовтий значок на кнопці налаштувань. Склеювання змін (кілька редагувань → одне; створили й видалили офлайн → нічого) і накладання черги на дані з сервера — `shared/outbox.js`.
- **Нагороди за офлайн-записи.** Сервер рахує «сьогодні/вчора» для нового запису від часу його створення на телефоні, якщо це не давніше ніж 7 днів (`rewardMoment` у `shared/game.js`) — тож монети й серія за дні без мережі не втрачаються.
- **Лише онлайн:** магазин, нагороди ачівок і перемикання тем (економіку рахує сервер) — без мережі ці кнопки неактивні. Публічний пошук теж потребує мережі; «Мої страви», ручне введення й калькулятор працюють.
- Для Vercel це нічого не змінює: ті самі функції й запити (або менше — зміни склеюються).

## Швидкодія

- **Миттєвий старт**: останні дані (профіль, страви, заміри, гра, статистика, сьогоднішній день) зберігаються знімком у localStorage, і головний екран малюється одразу, а свіжі дані приходять у фоні (`src/data/store.ts`, «Знімок для миттєвого старту»).
- **Чанки**: React і framer-motion — окремими файлами (їхній кеш переживає оновлення застосунку); шторки, DEV-панель і конфеті — лінивими чанками (`src/features/lazySheets.ts`), які підтягуються, коли браузер вільний.
- **Рендер**: без SVG-фільтрів на анімованих елементах (сяйво — напівпрозорі лінії), картки під першим екраном із `content-visibility: auto`, бліки й фонові ефекти на паузі під шторкою (атрибут `html[data-sheet]` замість дорогого `:has()`).

## Безкоштовні ліміти

Застосунок особистий (один користувач) і розрахований жити вічно на безкоштовних тарифах Vercel Hobby та Redis (Upstash Free через Vercel Marketplace):

- фонового опитування немає: дані оновлюються при поверненні в застосунок (не частіше ніж раз на 5 хвилин; одразу — якщо змінилась дата) і при поверненні мережі. Між оновленнями все видно зі знімка в localStorage і з власних змін;
- статика (JS, CSS, шрифти) — з CDN з `immutable`-кешем і з сервіс-воркера, тож повторні відкриття майже не витрачають трафік;
- один запит `/api/stats` віддає рік підсумків однією командою Redis (`ct:summary`), а збереження запису перевикористовує вже прочитані день і профіль;
- публічний пошук запускається лише через 350 мс після останнього символу, а результати кешуються на CDN Vercel і в Redis на добу;
- фото продуктів — напряму з CDN Сільпо, Zakaz.ua й Open Food Facts; Vercel Blob не використовується;
- публічний пошук — це один виклик функції, хоч би скільки джерел вона опитала: список і картки Сільпо, Zakaz.ua, OFF функція запитує сама;
- функцій 11 із 12 дозволених на Hobby (`api/ai.js` — фото етикетки через Gemini); крон — один раз на добу;
- фото етикетки (Gemini) — не частіше `AI_DAILY_LIMIT` на добу; «що дає найбільше калорій» — 28 HGETALL раз на добу (далі кеш).

Орієнтовне навантаження одного користувача: ~10 відкриттів і ~10 записів їжі на день → ≈ 150–250 викликів функцій і ≈ 200–300 команд Redis на день, тобто ≈ 5–8 тис. викликів і ≈ 6–9 тис. команд на місяць — на два порядки менше за безкоштовні ліміти. Дані ростуть на кілька КБ на день, тож місця в безкоштовному Redis вистачить на десятки років. Фактичне використання — у Vercel → Usage та в панелі Upstash.

Дані публічного пошуку — каталоги Сільпо, Zakaz.ua й Open Food Facts (ODbL).

## Теми (технічно)

Кольори задані CSS-змінними в `src/index.css` (`--bg-main`, `--bg-card`, `--accent-*`, `--font-app` тощо). Нова тема = блок `:root[data-theme='…']` у `src/themes.css`, товар у `shared/shop.js` (`THEME_IDS`, `SHOP_ITEMS`), зразки кольорів у `src/features/game/themeStyle.ts` і, за бажанням, ефект у `ThemeEffects`.
